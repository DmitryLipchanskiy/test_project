# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-14 · Сессия 2 · Playwright MCP v0.0.79

- **Тип:** MCP-сервер
- **Установка:** `claude mcp add playwright --scope project -- npx @playwright/mcp@latest`
- **Зачем:** интерактивная проверка страницы приложения — открыть стенд, читать
  дерево доступности, кликать, вводить значения, снимать доказательства.
  Нужен для проверок, которые нельзя закрыть `curl`: состояние корзины,
  поведение поля промокода, границы количества.
- **Область:** проект. Создан `.mcp.json` в корне — конфигурация видна
  в репозитории, проверяющий увидит её вместе с кодом.
- **Проверка:** `claude mcp list` показывает
  `playwright: npx @playwright/mcp@latest - ⏸ Pending approval (run claude to approve)`.
  Версия пакета уточнена через `npm view @playwright/mcp version` → `0.0.79`.
  **Инструменты сервера в текущей сессии недоступны:** MCP подключается при старте
  сессии и требует одобрения, поэтому фактические проверки этой сессии выполнены
  встроенным браузерным MCP (Claude Browser), а не Playwright MCP. Полноценная
  проверка Playwright MCP — при следующем запуске сессии; до этого запись считать
  неподтверждённой.

## 2026-08-14 · Сессия 3 · Playwright MCP v0.0.79 — **подтверждён**

- **Тип:** MCP-сервер (дополнение к записи выше, старая запись не редактировалась)
- **Установка:** повторная не требовалась — сервер поднялся из `.mcp.json`
  при старте сессии после одобрения.
- **Проверка:** инструменты сервера появились в сессии и доступны к вызову:
  `browser_navigate`, `browser_snapshot`, `browser_click`, `browser_type`,
  `browser_evaluate`, `browser_take_screenshot`, `browser_console_messages`,
  `browser_network_requests` и другие. Предыдущая пометка «неподтверждён» снята.
- **Чего в этой записи нет:** фреймворка `@playwright/test`. Это другой инструмент —
  MCP-сервер даёт интерактивный браузер агенту, фреймворк нужен для запускаемых
  `.spec.ts`-тестов. Ставится отдельно, в сессии автотеста, отдельной записью.

## 2026-08-15 · Сессия 5 · @playwright/test v1.62.1

- **Тип:** библиотека (тестовый фреймворк). **Не путать с Playwright MCP** из записей
  выше: MCP-сервер даёт агенту интерактивный браузер в сессии, фреймворк —
  запускаемые `.spec.ts`-тесты, которые прогоняются командой и в CI.
- **Установка:**
  ```
  npm init -y
  npm install -D @playwright/test
  npx playwright install chromium
  ```
- **Зачем:** автотесты на найденные дефекты. Четыре теста, по одному на баг,
  Page Object Model в `tests/pages/CartPage.ts`. Нужны как измерительный
  инструмент для фикса: после точечной починки один тест должен позеленеть,
  остальные три — остаться красными.
- **Область:** проект. `package.json` и `package-lock.json` коммитятся —
  по ним воспроизводится окружение. `node_modules/`, `test-results/`,
  `playwright-report/` в `.gitignore`.
- **Проверка:** `npx playwright --version` → `Version 1.62.1`.
  `npx playwright install chromium` → `Chrome Headless Shell 151.0.7922.34`.
  `npx playwright test` → **4 failed**, каждый тест падает на своём дефекте,
  вывод целиком сохранён в `qa/evidence/playwright-run-01-red.txt`.
  Красный прогон здесь и есть подтверждение работоспособности: тесты сверяют
  поведение со `SPEC.md`, а дефекты пока не исправлены.
