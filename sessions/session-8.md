## Размышления

### Требование прогнать инструкцию, а не перечитать её

Проверка README реальным прогоном — не формальность, а последняя возможность
поймать ту самую механику, которой посвящён весь список расхождений: инструкция
написана, выглядит правильной, шаги знакомы — значит работает. Ровно так же
выглядели «репозиторий инициализирован» и «стенд поднят».

Отдельная сложность: у меня окружение уже настроено — `node_modules` на месте,
Chromium скачан, стенд запущен с прошлой сессии. Прогон в таком состоянии
докажет только то, что команды не падают на готовом окружении, а проверять надо
инструкцию для человека, который клонировал репозиторий впервые. Поэтому перед
прогоном стенд останавливается: «поднимите сервер» должно сработать с нуля,
а не «сервер и так уже поднят».

Полностью чистым окружение не сделать, не удалив `node_modules` и кэш Playwright
(~95 МБ). Это отмечено как ограничение проверки, а не выдано за полную имитацию
первого запуска.

### Что в README обязано быть неудобным

Разделы «что не сделано», «что не покрыто», «допущения и ограничения» занимают
в README больше места, чем список достижений. Это осознанно: незаписанная
граница неотличима от недосмотра, и аудит это подтвердил — шесть его находок
были не ошибками, а именно границами, о которых мы нигде не сказали.

### Прогон инструкции: что показала проверка

Прогнал все пять шагов подряд, предварительно остановив стенд, чтобы шаг «поднять
сервер» проверялся честно. Результаты:

| Шаг | Команда | Результат |
|---|---|---|
| 1 | `npm install` | `added 1 package, and audited 5 packages`, `found 0 vulnerabilities` |
| 2 | `npx playwright install chromium` | **пустой вывод**, `exit=0` |
| 3 | `python3 -m http.server 8765` | PID 28211, `cwd` = корень проекта |
| 4 | `http://localhost:8765/app/index.html` | `200 OK`, `<title>Магазин «Наивная корзина»</title>`, каталог 8 позиций |
| 5 | `npx playwright test` | `1 passed, 3 failed` — как заявлено в README |

**Один шаг потребовал правки README.** Второй: при уже скачанном браузере
команда завершается молча, вообще без вывода. Падением это не является
(`exit=0`), но человек, следующий инструкции впервые, вправе засомневаться —
не молча ли она отказала. Дописал в README, что пустой вывод нормален,
и добавил способ проверить: `npx playwright install --dry-run chromium`
показывает пути установки.

Это ровно тот класс мелочи, ради которого требовался прогон, а не перечитывание:
по памяти я бы этот шаг описал как «скачивает браузер» и не заметил, что
в типичном случае он не скачивает ничего и ничего не говорит.

**Скриншот первого захода** снят и приложен к README (`readme-step4-app-opened.png`).
Первый вариант поймал состояние корзины от предыдущих проверок — в `localStorage`
браузера лежали товары и промокод с ТП-13. Пересняли с очищенным хранилищем:
инструкция описывает первый заход, а не продолжение чужой сессии.

**Ограничение проверки.** Полностью чистым окружение сделать не удалось:
`node_modules` и кэш Playwright (~95 МБ) остались с предыдущих сессий, поэтому
шаги 1 и 2 отработали в режиме «уже установлено». Проверено, что команды
не падают и дают понятный результат; проверка «с нуля на чистой машине»
требует клона репозитория в пустое окружение и здесь не выполнялась.
